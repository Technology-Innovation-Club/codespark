What could bite

Risks & how each is neutralized.

SSR frontend

Codespark's pages would SS but are indexable SPA today. Keep public pages SSR'd; make the 8 data-hub routes ssr:false (as they already were in the src hub) so Convex auth stays simple and reliable.

Geo-pin change

The hub uses supabase.auth.signInAnonymously + a profiles row. Convex Auth Anonymous + a one-row upsert is a clean swap; a tiny "your session will reset" risk for existing participants — acceptable is that env is new anyway.

Data fidelity

The books seed in migrations references Google-Drive UUIDs for covers/downloads. We port those rows verbatim into convex/seed.ts, so the coming list is byte-identical.

shadcn harness

The hub ships ~40 components/ui/* shadcn files, mostly unused. We only port the ones actually imported (sooner/sweep), dropping dead weight.

tanstack Start SSR + Convex

No official Start SSR adapter for Convex Auth yet (SSR is Next-first / beta). Mitigation: proof of the data-bound hub routes to CSR via ssr:false, public marking route SSI-safe.

Vite base + router basepath

Asset URLs (vite base) and app routes (router basepath) are two settings. Since the hub is a nested route group, not a separate build, no basepath is needed — the site stays domain-rooted.
